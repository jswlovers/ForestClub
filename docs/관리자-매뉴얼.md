## 1. 관리자 페이지 접속

- 주소: `https://도메인/admin.html` (로컬은 `http://localhost:3000/admin.html`)
- 관리자 계정의 이메일과 비밀번호로 로그인합니다. 일반 회원 계정으로 로그인하면 "관리자 계정이 아니에요"라고 나오며 로그아웃됩니다.
- 화면 위 **사이트로 이동**으로 회원 사이트에 갈 수 있습니다.
- 관리자 계정도 한 곳에서만 로그인됩니다. 다른 기기에서 로그인하면 기존 접속이 끊깁니다.

### 관리자 계정 만들기
- **최초 실행 시** 서버가 `.env`의 `ADMIN_EMAIL`, `ADMIN_PASSWORD`로 관리자 계정을 자동 생성합니다. 기본값은 `admin@forestclub.kr` / `admin1234!` 이므로 **운영 전 반드시 변경**해야 합니다.
- **기존 회원을 관리자로 승격**하려면 서버에서 다음을 실행합니다.

```bash
npm run make-admin -- someone@example.com
```

- 관리자 계정은 이용 정지할 수 없고, 다른 회원의 쪽지 대상·동행 신청 후보·공지 발송 대상에서 제외됩니다.

## 2. 일상 업무 체크리스트

| 주기 | 확인할 탭 | 할 일 |
|---|---|---|
| 매일 | 코인 충전 승인 | 대기중 요청과 실제 입금 내역을 대조해 승인/거절 |
| 매일 | 지원서 심사 | 대기중 지원서 검토 (안내 기한: 영업일 3일) |
| 매일 | 고객센터/신고 | 새 문의 처리, 환불 요청·회원 신고 우선 확인 |
| 매일 | 신분증 인증 | 대기중 신청 확인 후 승인/반려 |
| 수시 | 회원 관리 | 신고 건수가 높은 회원, 정지 회원 확인 |
| 주 1회 | 알림 발송 로그 | 발송 실패 건 점검 |
| 발송 전 | 카카오톡 발송 | 대상·미리보기 확인 후 발송 (친구톡은 주간에만) |

각 탭은 **접속 시 한 번 불러옵니다.** 새 요청을 보려면 페이지를 새로고침하세요.

## 3. 탭별 사용법

처리 버튼을 누르면 브라우저 입력창이 떠서 사유/메모를 물어봅니다. 입력은 대부분 선택이며, 취소를 누르면 빈 값으로 처리되니 주의하세요(처리 자체는 진행됩니다).

### 3-1. 회원 관리
전체 회원 목록입니다. 열: 이름, 이메일, 연락처, 역할, **보유 코인**, 상태, **신고**, 인증, 가입일, 처리.

- **이용 정지**: 정지 사유를 입력(선택)하면 해당 회원은 즉시 로그아웃되고 다시 로그인할 수 없습니다. 로그인 시 정지 사유가 회원에게 표시됩니다.
- **정지 해제**: 정지된 회원 행의 버튼으로 복구합니다.
- **신고 열**: 해당 회원에 대한 신고 누적 건수입니다. 3건 이상이면 경고, 5건 이상이면 정지 색상으로 강조됩니다.
- **인증 열**
  - 본인인증 상태는 표시만 됩니다. 부여/해제는 **신분증 인증 탭의 심사**로만 합니다.
  - **재직**, **골프** 버튼은 클릭으로 인증 배지를 켜고 끕니다(✓ 표시가 켜진 상태). 서류·확인 절차는 운영 기준대로 진행하시고, 확인이 끝난 회원에게 부여하세요. 회원이 직접 신청하는 화면은 없습니다.
- 이 탭이 열릴 때 **안내 메시지 발송**의 회원 선택 목록도 함께 채워집니다(연락처가 있는 회원만).

### 3-2. 지원서 심사
멤버십 지원서 목록입니다. 연령대, 지역, 직업, 골프 구력, 관심 분야, 추천인, 소개를 보고 판단합니다.

- **승인**: 승인 즉시 지원자에게 승인 문자가 갑니다.
- **거절**: 사유를 입력하면 문자와 지원자의 **내 지원 현황** 화면에 그대로 표시됩니다. 비워두면 기본 문구로 안내됩니다.
- 이미 처리된 지원서는 다시 처리할 수 없습니다(버튼이 사라짐).
- 서류 심사 후 진행하는 **멤버 인터뷰**는 시스템 밖에서 진행합니다. 인터뷰가 끝난 뒤에 승인 처리를 하는 것을 권장합니다.

### 3-3. 신분증 인증
회원이 올린 신분증 사진으로 본인 여부를 확인합니다.

1. 신분증 썸네일을 눌러 원본을 새 창에서 확인합니다. (본인과 관리자만 열람 가능한 비공개 파일입니다.)
2. 이름·사진 등이 가입 정보와 일치하는지 확인합니다.
3. **승인**하면 회원 프로필에 ✓ 본인인증 배지가 붙고 승인 문자가 갑니다. **반려**하면 사유와 함께 재신청 안내 문자가 갑니다.

주의: 신분증에는 민감한 개인정보가 들어 있습니다. 화면을 공유하거나 캡처를 보관하지 마시고, 확인 목적 외로 사용하지 마세요.

### 3-4. 동행 신청 현황
회원 간 동행 신청의 신청자, 대상, 모임, 메시지, 상태(대기중/수락됨/거절됨/취소됨)를 조회합니다. **조회 전용**이며 처리 권한은 회원 본인에게 있습니다.

### 3-5. 참가 문의
회원(또는 비회원)이 모임 카드의 **참가 문의/일정 문의**를 누른 내역입니다. 회원 이름 또는 "비회원", 모임명, 문의일이 표시됩니다. 조회 전용이며, 카드의 **남은 자리**는 모임별 문의 수를 정원에서 뺀 값으로 자동 계산됩니다.

### 3-6. 고객센터/신고
회원이 접수한 클레임/불만, 환불 요청, 회원 신고, 기타 문의입니다.

| 버튼 | 동작 |
|---|---|
| **처리중으로** | 상태를 처리중으로 바꾸고 회원에게 문자 발송 |
| **완료 처리** | 처리완료로 변경 (환불 요청 건은 이 버튼 대신 **환불 처리**가 표시됨) |
| **반려** | 반려 처리, 사유는 회원에게 함께 안내 |
| **환불 처리** | 환불할 **코인 수**를 입력하면 코인이 즉시 지급되고 처리완료로 변경, 문자 발송 |
| **회원 정지 / 정지 해제** | 회원 신고 건에서 신고 대상 회원을 바로 정지/해제 |

- 환불 요청에 회원이 충전 내역을 연결했다면 "대상/관련내역" 열에 금액과 코인이 표시됩니다.
- 환불은 이미 처리완료된 건에 중복으로 할 수 없습니다.
- 환불 지급은 코인 원장에 **환불 지급**으로 기록됩니다. 실제 **현금 환불(계좌 이체 등)은 시스템 밖에서 별도로** 진행해야 합니다. 이 화면의 환불 처리는 코인 잔액만 늘립니다.

### 3-7. 코인 충전 승인
회원이 무통장입금 등으로 신청한 충전 요청 목록입니다.

1. 신청 금액과 신청자를 확인합니다.
2. 실제 입금(입금자명·금액)을 통장과 대조합니다.
3. 일치하면 **승인**(메모에 입금자명·확인 내용을 남겨 두면 좋습니다). 코인이 즉시 지급되고 회원에게 문자가 갑니다.
4. 입금이 확인되지 않으면 **거절**하고 사유를 남깁니다.

- 승인·거절은 대기중 요청에만 가능하며, 한 번 처리하면 되돌릴 수 없습니다. **승인 전에 입금을 꼭 확인**하세요.
- 수단이 "토스페이먼츠"인 요청은 결제 연동 흐름의 건입니다(현재 회원 화면은 수동 입금만 노출).
- **회원 화면에는 입금 계좌 정보가 표시되지 않습니다.** 충전 신청 접수 후 회원에게 입금 계좌를 안내하는 절차(문자, 공지 등)를 운영에서 정해야 합니다. 안내 메시지 발송 탭을 활용할 수 있습니다.

### 3-8. 코인 원장
모든 코인 거래의 기록입니다(최근 내역 기준). [4장](#4-코인-운영-정책과-원장)을 참고하세요.

### 3-9. 안내 메시지 발송
결제 확인, 이벤트·점검 공지 등 자유 문구를 회원에게 보냅니다.

1. **받는 대상**: **전체 회원(연락처 등록자)** 또는 **특정 회원**을 선택합니다.
2. 메시지 내용을 입력합니다(최대 1,000자). 문자 길이는 통신사 기준에 따라 나뉘어 발송될 수 있으니 짧게 쓰는 것을 권합니다.
3. **발송하기**를 누릅니다. 전체 발송은 확인창이 한 번 더 뜹니다.
4. 결과가 "총 N건 중 성공 M건"으로 표시됩니다.

- 관리자 계정과 연락처가 없는 회원은 대상에서 제외됩니다.
- **한 번 보낸 메시지는 취소할 수 없습니다.** 특히 전체 발송 전에는 오탈자와 내용을 다시 확인하세요.
- 남용 방지를 위해 10분에 20회까지만 발송할 수 있습니다.
- 카카오 알림톡으로 나가려면 `KAKAO_TEMPLATE_ADMIN_NOTICE`가 설정되어야 하며, 그렇지 않으면 문자로 발송됩니다.

### 3-10. 카카오톡 발송
회원에게 카카오톡으로 메시지를 보내는 화면입니다. 위쪽 상태 박스에 **알림톡/친구톡이 실제 발송인지 모의 발송인지**, 그리고 광고 수신에 동의한 회원 수가 표시됩니다.

**메시지 종류 (둘 중 하나 선택)**

| 종류 | 언제 쓰나요 | 수신 동의 | 조건 |
|---|---|---|---|
| **알림톡** | 결제 확인, 일정 변경 등 회원이 알아야 하는 **정보성 안내** | 필요 없음 | 카카오에서 승인받은 템플릿(`KAKAO_TEMPLATE_ADMIN_NOTICE`) 필요. 홍보·이벤트 내용은 넣으면 안 됩니다 |
| **친구톡** | 이벤트, 신규 모임 오픈 등 **광고성 소식** | **광고 수신에 동의한 회원만** | 카카오 채널을 친구 추가한 회원에게만 도달. 오후 8시 50분~오전 8시에는 발송 불가 |

**받는 대상**: 전체 회원 / 멤버십 승인 회원 / 본인 인증 완료 회원 / 골프 관심 회원 / 여행 관심 회원 / 특정 회원 1명. 관리자, 연락처가 없는 회원, 정지된 회원은 항상 제외됩니다. (관심 회원은 회원이 프로필에 입력한 관심 분야 기준이며, "골프·여행 모두"는 양쪽에 포함됩니다.)

**발송 순서**

1. 메시지 종류와 대상을 고르고 내용을 입력합니다(최대 900자).
2. **대상·미리보기 확인**을 눌러 받는 사람 수, 동의하지 않아 제외되는 인원, 실제로 나갈 문구를 확인합니다.
3. **발송하기**를 누르고 확인창에서 인원을 다시 확인한 뒤 진행합니다.
4. 아래 **발송 이력**에서 대상 인원, 발송됨, 모의발송, 실패, 동의 없어 제외된 인원을 확인합니다. 회원별 결과는 **알림 발송 로그** 탭에서 볼 수 있습니다.

**친구톡 문구는 자동으로 다음과 같이 나갑니다.**
```
(광고)[포레스트클럽] (입력한 내용)

무료수신거부: 채널 차단
```

주의

- 보낸 메시지는 취소할 수 없습니다. 미리보기로 꼭 확인하세요.
- 친구톡은 친구 추가하지 않은 회원에게는 전달되지 않고 **실패로 기록**됩니다. 문자로 대신 보내지 않습니다. 회원들에게 카카오 채널 친구 추가를 안내해 주세요.
- 알림톡은 카카오 쪽에서 실패하면 문자(SMS)로 자동 대체 발송됩니다.
- 카카오 키·채널·템플릿이 없는 동안은 **모의 발송**(기록만 남고 실제로는 나가지 않음)으로 동작합니다. 상태 박스가 빨간 글씨면 실제 발송이 아닙니다.
- 한 번에 최대 1,000명, 10분에 10회까지 발송할 수 있습니다.
- 광고성 메시지는 정보통신망법의 적용을 받습니다. 수신 동의 여부는 회원이 프로필에서 직접 설정하며, 이 화면은 동의한 회원에게만 친구톡을 보냅니다.

기존 **안내 메시지 발송** 탭은 문자 위주의 단순 안내용이고, **카카오톡 발송** 탭은 카카오톡 전용으로 대상 선택, 수신 동의 확인, 발송 이력을 제공합니다.

### 3-11. 알림 발송 로그
시스템이 보낸 모든 알림의 최근 200건입니다. 수신 회원, 전화번호, 채널(SMS / 카카오 알림톡), 메시지, 상태, 일시가 표시됩니다.

| 상태 | 의미 |
|---|---|
| 발송됨 | 실제 발송 성공 |
| 모의발송 | 실제로 보내지 않고 기록만 함 (SMS_PROVIDER=mock일 때) |
| 발송실패 | 발송 시도 실패. 번호·잔액·API 키 점검 필요 |

**"모의발송"만 보인다면 실제 문자가 나가지 않는 상태입니다.** 운영 전 [7장](#7-서버-설정과-배포-전-점검)에서 SMS 설정을 완료해야 합니다.

## 4. 코인 운영 정책과 원장

### 요금 정책 (현재 값)
| 항목 | 값 | 변경 위치 |
|---|---|---|
| 환율 | 1코인 = 1원 | server/routes/coins.js |
| 최소 충전 | 1,000원 | server/routes/coins.js |
| 쪽지 1건 | 500코인 | server/routes/messages.js |
| 보이스톡 | 초당 10코인 | server/call-pricing.js |
| 페이스톡 | 초당 100코인 | server/call-pricing.js |
| 통화 시작/참여 최소 잔액 | 3,000코인 초과 | server/call-pricing.js |
| 통화 중 강제 종료 잔액 | 1,500코인 이하 | server/call-pricing.js |

요금을 바꾸려면 코드 수정이 필요합니다. 통화 요금은 프런트엔드(public/assets/app.js)에도 같은 값이 복사되어 있으니 **양쪽을 같이 바꿔야** 합니다.

### 복식부기 원장
모든 코인 이동은 두 줄(차변·대변)이 한 쌍으로 기록되며 같은 **거래그룹**으로 묶입니다.

| 거래 | 차변 | 대변 |
|---|---|---|
| 코인 충전 | 플랫폼 현금 | 회원 코인계정 |
| 쪽지·통화 사용 | 회원 코인계정 | 플랫폼 매출 |

회원의 코인 잔액은 저장된 숫자가 아니라 **원장에서 매번 계산**되므로, 원장이 곧 정본입니다. 종류 열에는 코인 충전 / 쪽지 발송 / 보이스톡 이용 / 페이스톡 이용 / 환불 지급이 표시됩니다.

- 통화는 1초마다 한 줄씩 기록되므로 원장에 통화 기록이 많이 쌓일 수 있습니다. 원장 탭은 **최근 내역만** 보여줍니다.
- 회원 잔액 문의가 있으면 회원 관리의 **보유 코인**과 원장의 해당 회원 계정 내역을 대조하세요.

## 5. 자동 제재 규칙

회원 신고가 접수되면 시스템이 즉시 다음과 같이 처리합니다.

| 같은 회원에 대한 신고 누적 | 자동 조치 |
|---|---|
| **3건** | 경고 문자 발송 (연락처가 있는 경우) |
| **5건** | 계정 자동 정지(사유: "신고 누적(5건) 자동 정지") + 정지 안내 문자 |

- 각 안내는 임계치에 처음 도달한 순간에만 한 번 발송됩니다.
- 자동 정지는 **신고 횟수만으로** 이뤄지므로 다수의 악의적 신고에 의한 오정지 가능성이 있습니다. 자동 정지된 회원은 **고객센터/신고 탭에서 신고 내용을 검토한 뒤** 부당하다면 **회원 관리 탭의 정지 해제**로 복구하세요.
- 기준 값은 server/moderation.js (WARN_THRESHOLD, SUSPEND_THRESHOLD), 관리자 화면 색 표시 기준은 public/assets/admin.js에 있으며 바꿀 때 양쪽을 맞춰야 합니다.

## 6. 알림 발송 구조

시스템은 다음 상황에서 자동으로 알림을 보냅니다. 관리자가 별도로 보낼 필요가 없습니다.

| 상황 | 수신자 |
|---|---|
| 회원가입 | 가입자 |
| 지원서 접수 / 승인 / 거절 | 지원자 |
| 동행 신청 받음 / 신청 결과 | 대상 회원 / 신청자 |
| 비밀번호 재설정 인증코드 | 요청 회원 |
| 코인 충전 승인 / 거절 | 신청 회원 |
| 새 쪽지 | 받는 회원 |
| 고객센터 문의 상태 변경 / 환불 처리 | 문의 회원 |
| 본인 인증 승인 / 반려 | 신청 회원 |
| 신고 누적 경고 / 자동 정지 | 신고 대상 회원 |

- 연락처가 없는 회원에게는 발송되지 않습니다.
- 카카오 알림톡 템플릿을 등록한 종류는 알림톡으로 먼저 발송하고 실패하면 문자로 대체합니다. 등록하지 않은 종류는 문자로 나갑니다.
- 모든 발송 결과는 [알림 발송 로그](#3-11-알림-발송-로그) 탭에서 확인합니다.

## 7. 서버 설정과 배포 전 점검

### 실행
```bash
npm install
npm start        # http://localhost:3000
npm run dev      # 개발 중 (파일 변경 시 자동 재시작)
```
Node.js 22.6 이상이 필요합니다. 첫 실행 시 데이터베이스(`data/forest-club.sqlite`)가 자동 생성됩니다.

### 운영 배포 전 체크리스트
- [ ] `.env`의 `ADMIN_EMAIL`, `ADMIN_PASSWORD`를 실제 값으로 변경 (기본 비밀번호 사용 금지)
- [ ] HTTPS 서비스라면 `NODE_ENV=production` (세션 쿠키에 secure 적용)
- [ ] Nginx 등 리버스 프록시 뒤라면 `TRUST_PROXY=true`, **프록시가 없다면 켜지 마세요** (켜면 요청 제한을 우회당할 수 있음)
- [ ] SMS 실발송 설정 (아래)
- [ ] 코인 충전용 입금 계좌 안내 방법 결정
- [ ] `data/` 폴더 정기 백업 (DB와 업로드 파일이 모두 여기 저장됨)
- [ ] 서버 방화벽/접근 권한으로 `data/` 폴더가 외부에서 직접 열리지 않는지 확인

### 알림 설정 (.env)
`.env.example`을 복사해 `.env`를 만듭니다.

- **SMS**: 기본값은 `SMS_PROVIDER=mock`(실제 발송 안 함). 실발송하려면 `SMS_PROVIDER=solapi`로 바꾸고 `SOLAPI_API_KEY`, `SOLAPI_API_SECRET`, `SOLAPI_SENDER`(승인된 발신번호)를 채웁니다. 코드 수정 없이 바로 전환됩니다.
- **카카오 알림톡(선택)**: 카카오 비즈니스 채널을 만들고 알림 종류별 템플릿을 심사 승인받은 뒤 `KAKAO_PF_ID`와 `KAKAO_TEMPLATE_*` 값을 채웁니다(SOLAPI 키도 필요). 공지용 `KAKAO_TEMPLATE_ADMIN_NOTICE`는 변수 하나(`#{message}`)만 넣은 템플릿으로 등록합니다.

### 카카오톡 발송 시작하기 (알림톡·친구톡)
카카오톡 발송 탭에서 실제로 메시지를 보내려면 아래 준비가 필요합니다. 준비되기 전에는 모의 발송으로만 동작합니다.

1. 카카오 비즈니스 채널을 만듭니다(https://business.kakao.com).
2. Solapi 계정을 만들고 카카오 채널을 연동한 뒤 발신번호를 등록합니다.
3. `.env`에 `SOLAPI_API_KEY`, `SOLAPI_API_SECRET`, `SOLAPI_SENDER`, `KAKAO_PF_ID`(채널 ID)를 채웁니다. → **친구톡 활성화**
4. 정보성 안내용 알림톡 템플릿을 만들어 심사 승인을 받고(변수는 `#{message}` 하나만), `KAKAO_TEMPLATE_ADMIN_NOTICE`에 승인된 템플릿 ID를 채웁니다. → **알림톡 활성화**
5. 서버를 재시작하고 카카오톡 발송 탭 상단 상태 박스가 "실제 발송"으로 바뀌었는지 확인합니다.
6. 처음에는 **특정 회원 1명(본인)**을 대상으로 시험 발송해 결과를 확인한 뒤 단체 발송을 하세요.

### 통화 기능 설정 (선택)
[Daily.co](https://dashboard.daily.co) 계정을 만들고 `DAILY_API_KEY`를 채우면 보이스톡/페이스톡이 활성화됩니다. 비워 두면 회원에게 "통화 기능이 아직 설정되지 않았어요"라고 안내됩니다.

### 결제 연동 (선택)
`TOSS_SECRET_KEY`를 채우면 서버의 토스페이먼츠 결제 승인 API가 활성화됩니다. 다만 회원 화면에 토스 결제 위젯은 아직 붙어 있지 않아, 현재는 **무통장입금 + 관리자 수동 승인** 방식만 실제로 사용됩니다.

## 8. 자주 겪는 문제

**회원이 "코인 충전했는데 반영이 안 돼요"라고 문의해요.**
코인 충전 승인 탭에서 해당 요청이 대기중인지 확인하세요. 입금이 확인되면 승인하면 즉시 반영됩니다.

**알림 로그가 전부 "모의발송"이에요.**
`SMS_PROVIDER=mock` 상태입니다. SOLAPI 설정을 완료하고 서버를 재시작하세요.

**회원이 로그인이 안 된다고 해요.**
회원 관리에서 상태가 "정지됨"인지 확인하세요. 정지된 계정은 로그인 시 정지 사유가 표시됩니다. 짧은 시간에 로그인을 반복하면 일시적으로 제한될 수도 있습니다.

**회원이 비밀번호 재설정 인증코드를 못 받아요.**
연락처를 등록하지 않은 회원은 코드를 받을 수 없습니다. 알림 발송 로그에서 발송 상태를 확인하세요. 필요하면 운영진이 회원 본인 확인 후 별도로 조치해야 합니다(관리자 화면에서 비밀번호를 직접 바꾸는 기능은 없습니다).

**잘못 승인한 충전이나 지원서를 되돌리고 싶어요.**
승인/거절은 화면에서 되돌릴 수 없습니다. 충전을 잘못 승인했다면 회원과 협의해 처리해야 하며, 원장 기록은 삭제되지 않고 남습니다.

**서버를 옮기거나 복구해야 해요.**
`data/` 폴더(데이터베이스 + 업로드 파일)를 통째로 복사하면 됩니다. `.env`도 함께 옮기세요.
