## 1. 카카오톡 메시지 센터 (구현 완료)

### 1-1. 왜 필요했나
기존에도 카카오 알림톡 연동은 있었지만 다음이 부족했습니다.

| 기존 상태 | 문제 |
|---|---|
| 알림톡은 미리 승인된 템플릿 문구만 전송 | 이벤트·신규 모임 소식 같은 자유 문구를 보낼 수 없음 |
| 템플릿이 없으면 조용히 문자(SMS)로 발송 | "카톡으로 보냈다"고 착각할 수 있음 |
| 발송 대상이 "전체" 또는 "1명"뿐 | 골프 관심 회원처럼 대상을 좁혀 보낼 수 없음 |
| 광고 수신 동의를 받는 곳이 없음 | 광고성 메시지를 보낼 법적 근거가 없음 |
| 발송 단위의 이력이 없음 | 누가 언제 누구에게 무엇을 보냈는지 한눈에 볼 수 없음 |

### 1-2. 두 가지 발송 방식

| | 알림톡 | 친구톡 |
|---|---|---|
| 용도 | 정보성 안내 (결제 확인, 일정 변경) | 광고성 소식 (이벤트, 신규 모임) |
| 문구 | 승인된 템플릿의 변수 `#{message}`에 문구 삽입 | 자유 문구 |
| 수신 동의 | 불필요 | **광고 수신 동의 회원만** |
| 도달 조건 | 연락처만 있으면 됨 | 카카오 채널을 **친구 추가**한 회원 |
| 실패 시 | 문자(SMS)로 자동 대체 | 대체 없음 (광고 문자 이중 발송 방지) |
| 자동 처리 | - | `(광고)[포레스트클럽]` 앞 표기, `무료수신거부: 채널 차단` 뒤 문구, 야간(20:50~08:00) 발송 차단 |

친구톡을 항상 광고성으로 취급해 "동의 확인, 광고 표기, 야간 차단"을 시스템이 강제합니다. 담당자가 실수로 규정을 어기지 못하게 하려는 설계입니다.

### 1-3. 화면 구성

**회원 화면 (내 프로필)**

- "[선택] 카카오톡·문자로 이벤트, 모임 소식 등 광고성 정보를 받겠습니다" 체크박스
- 결제·승인 결과 같은 안내 알림은 동의와 무관하게 발송된다는 안내 문구
- 동의 시각은 처음 동의한 시점을 유지하고, 해제하면 즉시 발송 대상에서 빠집니다.

**관리자 화면 (카카오톡 발송 탭)**

1. 상태 박스: 알림톡/친구톡이 "실제 발송"인지 "모의 발송"인지, 광고 수신 동의 회원 수, 지금이 야간 차단 시간인지
2. 발송 폼: 종류 → 대상 → 내용(900자) → **대상·미리보기 확인** → 발송
3. 미리보기: 받는 사람 수, 동의하지 않아 제외되는 인원, 실제로 나갈 최종 문구
4. 발송 이력 표: 일시, 종류, 대상, 메시지, 대상 인원/발송됨/모의발송/실패/동의 없어 제외

### 1-4. 받는 대상

| 대상 | 기준 |
|---|---|
| 전체 회원 | 관리자 제외, 연락처 있음, 정지되지 않음 |
| 멤버십 승인 회원 | 승인된 지원서가 있는 회원 |
| 본인 인증 완료 회원 | 신분증 인증이 승인된 회원 |
| 골프 / 여행 관심 회원 | 프로필 관심 분야가 해당 분야 또는 "둘 다" |
| 특정 회원 1명 | 시험 발송이나 개별 안내용 |

친구톡은 위 대상 중 **광고 수신 동의 회원만** 남깁니다.

### 1-5. 처리 흐름

```
관리자 입력 → 검증(종류·대상·길이·야간 시간)
  → 대상 회원 조회 (연락처·정지·관리자 제외, 친구톡이면 동의자만)
  → 발송 이력(kakao_campaigns) 생성
  → 10명씩 묶어 발송 → 회원별 결과를 notifications 테이블에 기록
  → 이력에 발송됨/모의/실패 집계 저장
```

### 1-6. 데이터 변경

| 대상 | 변경 |
|---|---|
| `users.marketing_opt_in_at` (신규) | 광고 수신 동의 일시. 비어 있으면 미동의 |
| `kakao_campaigns` (신규 테이블) | 발송 단위 이력: 종류, 대상, 문구, 인원 집계, 발송자 |
| `notifications.campaign_id` (신규) | 회원별 발송 기록을 발송 이력과 연결 |

### 1-7. API

| 메서드 · 경로 | 설명 |
|---|---|
| `GET /api/admin/kakao/status` | 실제/모의 여부, 동의 회원 수, 야간 여부 |
| `GET /api/admin/kakao/preview` | 종류·대상별 수신 인원과 제외 인원 |
| `POST /api/admin/kakao/send` | 발송 (10분에 10회, 최대 1,000명, 900자) |
| `GET /api/admin/kakao/campaigns` | 최근 100건 발송 이력 |
| `PATCH /api/auth/profile` (`marketingOptIn`) | 회원의 동의/해제 |

모든 관리자 API는 관리자 로그인이 필요합니다.

### 1-8. 검증한 내용
격리된 임시 복사본에서 자동 테스트로 아래를 확인했습니다. 모두 통과했습니다.

- 동의 저장·해제, 동의 값이 없는 프로필 저장이 동의를 지우지 않는지
- 일반 회원 접근 차단(403)과 비로그인 차단(401)
- 알림톡은 동의와 무관하게, 친구톡은 동의자만 대상이 되는지
- 관심 분야·특정 회원 대상 선정, 연락처 없는 회원 제외
- 친구톡의 `(광고)` 표기·무료수신거부 문구 자동 삽입
- 야간 차단 경계 시각(20:49 허용, 20:50 차단, 07:59 차단, 08:00 허용)
- 빈 메시지, 901자 초과, 잘못된 대상 거부, 발송 이력과 알림 로그 연결

### 1-9. 아직 확인되지 않은 것과 한계
- **실제 카카오 발송은 시험하지 못했습니다.** 카카오 채널·Solapi 계정·승인된 템플릿이 없어 모의 발송으로만 검증했습니다. 친구톡 요청 형식(`type: 'CTA'`, `adFlag`)은 Solapi 문서 기준으로 작성했으므로, 채널 준비 후 **본인 1명에게 시험 발송**해서 확인해 주세요.
- 친구톡 야간 차단 시간(20:50~08:00)은 카카오 정책 기준으로 넣었습니다. 정책이 바뀌면 `server/services/kakao-campaign.js`의 `isNightWindow`를 수정합니다.
- 회원이 카카오 채널을 친구 추가했는지 시스템이 알 수 없어, 친구가 아닌 회원은 발송 결과에서 실패로 나옵니다. (개선안: 3-4의 카카오 로그인·채널 연동)
- 예약 발송, 이미지·버튼이 들어간 친구톡은 아직 없습니다.
- 광고 수신 동의를 회원가입 화면에서는 받지 않고 프로필에서만 받습니다.

### 1-10. 운영 시작 체크리스트
1. 카카오 비즈니스 채널 개설
2. Solapi 계정 생성, 채널 연동, 발신번호 등록
3. `.env`에 `SOLAPI_API_KEY`, `SOLAPI_API_SECRET`, `SOLAPI_SENDER`, `KAKAO_PF_ID` 입력 → 친구톡 활성화
4. 정보성 알림톡 템플릿(변수 `#{message}` 하나) 심사 승인 후 `KAKAO_TEMPLATE_ADMIN_NOTICE` 입력 → 알림톡 활성화
5. 서버 재시작 후 카카오톡 발송 탭 상태 박스 확인
6. **특정 회원 1명(본인)**에게 시험 발송
7. 회원들에게 채널 친구 추가와 프로필의 광고 수신 동의를 안내

## 2. 추가 기능 제안 로드맵

우선순위: **P1** 서비스 신뢰·안전에 직결, **P2** 운영 효율과 매출, **P3** 있으면 좋은 기능. 규모: **S** 반나절~1일, **M** 2~4일, **L** 1주 이상.

| 순위 | 기능 | 지금의 공백 (코드 기준) | 규모 |
|---|---|---|---|
| P1 | **멤버십 승인과 계정 권한 연결** | 지원서를 승인해도 계정에 반영되지 않음. 가입만 하면 누구나 쪽지·동행 신청·통화 가능 | M |
| P1 | **회원 탈퇴와 개인정보 보관 정책** | 탈퇴 기능이 없음. 신분증 사진이 기간 제한 없이 서버에 남음 | M |
| P1 | **회원 차단·대화 거부** | 신고만 가능. 원치 않는 회원의 쪽지를 막을 방법이 없음 | S |
| P1 | **관리자 작업 기록(감사 로그)** | 승인·환불·정지를 누가 했는지 기록이 없음 | S |
| P2 | **모임 관리 (DB화)** | 모임이 코드(`events-catalog.js`)에 고정. 일정·참가비·정원 변경에 개발자가 필요 | L |
| P2 | **모임 참가 신청·결제·대기자** | "참가 문의"만 있고 실제 신청, 참가비 결제, 취소·환불이 없음 | L |
| P2 | **토스페이먼츠 자동 충전** | 서버 승인 API만 있고 결제 화면이 없어 관리자가 입금을 수동 확인 | M |
| P2 | **카카오 로그인·채널 연동** | 이메일 가입만 가능. 채널 친구 여부를 알 수 없음 | M |
| P2 | **관리자 회원 상세·메모** | 회원 목록만 있음. 이력(지원·충전·신고·문의)을 한 화면에서 볼 수 없음 | M |
| P2 | **운영 대시보드** | 가입·매출·충전 승인 대기 같은 지표가 없음 | M |
| P2 | **예약 발송·템플릿 저장 (카톡 센터 확장)** | 발송은 즉시만 가능 | S |
| P3 | 관리자의 회원 비밀번호 초기화 | 연락처 없는 회원은 복구 불가 | S |
| P3 | 회원 후기·게시판 | 후기가 화면에 고정 문구 | M |
| P3 | 일정 캘린더·모임 전 리마인드 알림 | 모임 전 안내를 수동으로 발송 | M |
| P3 | 이메일 알림 | 문자·카톡 외 채널 없음 | S |
| P3 | 데이터 백업 자동화 | `data/` 폴더를 수동으로 복사 | S |

## 3. 우선순위 높은 기능 상세

### 3-1. 멤버십 승인과 계정 권한 연결 (P1)
**문제**: 지원서를 승인해도 지원자의 계정 상태는 바뀌지 않습니다. 회원가입만 하면 심사 없이 코인 충전, 쪽지, 동행 신청이 모두 가능해 "초대제 프리미엄 클럽"이라는 서비스 성격과 맞지 않습니다.

**설계**

- `users.membership_status` 추가: `applicant`(가입만) → `member`(승인) / `rejected`
- 지원서 승인 시 해당 회원을 `member`로 변경 (승인 취소 시 되돌리는 관리자 버튼도 추가)
- `member`만 쪽지함, 동행 신청, 통화, 코인 충전 이용 가능. `applicant`는 지원서·프로필·고객센터만 사용
- 기존 회원은 마이그레이션 때 승인 기록이 있으면 `member`, 없으면 `applicant`로 정리(운영진이 일괄 승인 화면에서 확인)
- 동행 후보·쪽지 대상 목록도 `member`만 노출

**결정할 것**: 이미 가입한 회원을 어떻게 처리할지(전원 승인 vs 심사 다시).

### 3-2. 회원 탈퇴와 개인정보 보관 정책 (P1)
- 설정에서 **회원 탈퇴** 버튼: 비밀번호 확인 후 계정 비활성화, 이름·연락처·이메일 등 개인정보 삭제 또는 익명화
- 남은 코인이 있으면 탈퇴 전에 환불 요청 안내. 코인 원장은 회계 목적으로 익명 상태로 보존
- 신분증 사진은 **승인·반려 후 30일 뒤 자동 삭제**(기간은 운영 정책으로 결정), 인증 완료 사실(배지)만 유지
- 발송 로그·문의 내역의 보관 기간 정리

**결정할 것**: 신분증 보관 기간, 탈퇴 후 재가입 제한 여부.

### 3-3. 회원 차단 (P1)
- 대화창 메뉴에 **차단** 추가. 차단하면 상대는 나에게 쪽지·동행 신청·통화 요청 불가
- 차단당한 사실은 상대에게 직접 알리지 않고 "전송할 수 없어요"로만 안내
- 차단 목록 화면에서 해제. 기존 신고 기능과 별개로 동작

### 3-4. 카카오 로그인·채널 연동 (P2)
- 카카오 로그인 버튼으로 간편 가입·로그인 (이메일·이름·연락처 동의항목 활용)
- 카카오 API의 채널 친구 여부 조회로 **친구가 아닌 회원을 미리 걸러** 친구톡 실패를 줄이고, 프로필에 "채널 추가하기" 버튼 노출
- 기존 이메일 계정과 카카오 계정 연결(이메일 일치 시 연결 확인)

**선행 조건**: 카카오 디벨로퍼스 앱 등록, 비즈 앱 전환(연락처 동의항목).

### 3-5. 모임 관리와 참가 신청·결제 (P2)
- 관리자 화면에서 **모임 등록·수정**: 이름, 종류(골프/여행), 일정, 장소, 정원, 참가비, 신청 마감
- 회원 참가 신청 → 관리자 승인 → 참가비 결제(코인 또는 계좌 입금) → 확정. 정원 초과 시 **대기자**로 등록하고 자리가 나면 알림
- 취소·환불 규정(모임 며칠 전까지 전액 환불 등)을 모임별로 설정
- 확정된 참가자에게 **모임 전날 카카오톡 리마인드** 자동 발송(카톡 센터 활용)
- 현재 "참가 문의"·"동행 신청"은 새 모임 데이터와 연결

### 3-6. 관리자 작업 기록 (P1)
- `admin_audit_log` 테이블: 관리자, 행동(승인·환불·정지·인증 부여 등), 대상, 전후 값, 일시
- 관리자 화면에 검색 가능한 로그 탭. 삭제·수정 불가
- 환불·정지·코인 지급 같은 민감 작업을 여러 관리자가 나눠 할 때 책임 추적에 필요

## 4. 권장 진행 순서

| 단계 | 내용 | 이유 |
|---|---|---|
| 0 | **카카오톡 실발송 시험** (채널·Solapi·템플릿 준비) | 이번에 만든 기능을 실제로 검증하는 단계 |
| 1 | 멤버십 승인 연결 → 회원 차단 → 관리자 작업 기록 | 클럽의 신뢰와 안전을 지키는 기본 장치. 각각 작아서 함께 진행 가능 |
| 2 | 회원 탈퇴·개인정보 보관 정책 | 회원이 늘기 전에 정리. 법적 리스크 |
| 3 | 토스페이먼츠 자동 충전 → 관리자 회원 상세 | 운영자의 수작업 감소 |
| 4 | 모임 관리·참가 신청·결제, 카카오 로그인·채널 연동 | 가장 큰 작업. 1~3단계로 기반이 갖춰진 뒤 진행 |

먼저 정해 주실 것: (1) 기존 가입 회원을 어떻게 처리할지(3-1), (2) 신분증 보관 기간(3-2), (3) 코인 충전 입금 계좌 안내 방식.
